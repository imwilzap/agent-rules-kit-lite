# AGENTS.md: Python + FastAPI

Instructions for AI coding agents working in a FastAPI service on Python 3.12+ with Pydantic v2, SQLAlchemy 2.x, Alembic, pytest, and ruff.
Every line is a fact, a guard against a known agent mistake, or a verification step. Edit **Commands** and **Project map** to match this repo, and delete rules that do not apply.

## Commands
Run from the repo root. Commands assume uv. Replace the `uv run` prefix with your environment manager, and replace mypy with pyright if the repo uses it. `fastapi dev` needs `fastapi[standard]` and finds the app through `[tool.fastapi] entrypoint` in `pyproject.toml` or a conventional `main.py`; containers use `fastapi run`. `alembic check` needs a database that is at `head`.

**Verify** (run these before you say a task is done):
- Format check: `uv run ruff format --check .`
- Lint: `uv run ruff check .`
- Types: `uv run mypy .`
- Test: `uv run pytest -q`

**Other** (run only when asked or when the task needs it):
- Install: `uv sync`
- Dev server: `uv run fastapi dev`
- Apply migrations: `uv run alembic upgrade head`
- New migration: `uv run alembic revision --autogenerate -m "short message"`
- Migration drift: `uv run alembic check`

## Project map
- `app/main.py` builds the app and its `lifespan`. `app/api/` holds routers.
- `app/schemas/` holds Pydantic models. `app/models/` holds SQLAlchemy models.
- `app/services/` holds business logic. `app/core/` holds settings, security, and shared dependencies.
- `alembic/` holds migrations. `tests/` mirrors `app/`.

## Working agreement
- Read the files you will change, plus one neighboring file that does a similar job, before writing code. Match the patterns already in the repo.
- For work that touches more than two files, post a 2-4 line plan first. Ask one specific question when a requirement is ambiguous or the change is hard to undo.
- Keep each diff to one concern. Leave unrelated code, formatting, and comments as they are.
- Reproduce a bug with a failing test before fixing it whenever a test can express it.
- Run the commands in the Verify list that apply before you say a task is done, and report each command with its result. State plainly anything you could not run. Run the Other commands only when asked or when the task needs them.
- Ask before adding a dependency, editing CI config, changing a lockfile by hand, deleting files, or touching data migrations that may already be applied.
- Read the installed version's docs or source when unsure of an API. Use only functions and options you have seen in this repo, its dependencies, or their docs.
- Keep secrets, tokens, and personal data out of code, tests, fixtures, logs, and chat output. Read config from the environment.
- Commit, push, or open pull requests only when asked.

## Conventions
- Keep routers thin: parse the request, call a service function, return a response model. Put business rules in `services/` and queries beside them.
- Use separate Pydantic v2 models for input and output (`ItemCreate`, `ItemUpdate`, `ItemRead`). Return read models, set `response_model`, and never expose ORM objects or password hashes.
- Use Pydantic v2 APIs: `model_validate`, `model_dump`, `field_validator`, `ConfigDict(from_attributes=True)`. Set `extra="forbid"` on input models so unknown fields return 422 instead of being silently dropped.
- Declare dependencies as `Annotated[Type, Depends(provider)]` aliases and reuse them for the session, current user, and settings.
- Write `async def` endpoints only when every call inside is non-blocking. Use plain `def` for endpoints that call blocking libraries, and use `anyio.to_thread.run_sync` for blocking work inside async code.
- Create startup and shutdown resources (engine, HTTP clients) in a `lifespan` context manager attached to `FastAPI(lifespan=...)`, and close them after the `yield`. Event handlers are deprecated and do not run when `lifespan` is set.
- Write SQLAlchemy 2.x queries with `select()` and `session.execute()` or `session.scalars()`. Load relationships up front with `selectinload` or `joinedload`, or declare them `lazy="raise"` so a missed load fails loudly.
- Build one `async_sessionmaker(engine, expire_on_commit=False)`, yield one `AsyncSession` per request from a dependency, and open a separate session for each task under `asyncio.gather`. Dispose the engine at shutdown.
- Raise `HTTPException` at the API layer only. Raise domain exceptions in services and map them with exception handlers so every error body has one shape.
- Load configuration with `pydantic-settings` in one cached `get_settings()`. Read `os.environ` nowhere else.
- Annotate every function. Keep the type checker clean without blanket `# type: ignore`.
- Change the schema only through Alembic migrations. Read each autogenerated migration before committing it: autogenerate misses some changes and reports a rename as drop plus add, which loses data until you hand-edit it into `op.alter_column` or `op.rename_table`.
- Give `MetaData` a `naming_convention` so constraints and indexes get stable names that migrations can drop later.

## Known agent mistakes
Check your diff against this list before you finish.
- Calling `requests`, `time.sleep`, or a sync DB driver inside `async def`, which stalls the whole event loop.
- Writing Pydantic v1 idioms: `.dict()`, `.parse_obj()`, `@validator`, `class Config`, `orm_mode`.
- Using `@app.on_event("startup")`. Use `lifespan`.
- Touching a lazy relationship on an async session, which raises `MissingGreenlet`. Load it in the query.
- Reading attributes after `commit()` on a session with the default `expire_on_commit=True`, which triggers a lazy refresh and `MissingGreenlet`.
- Sharing one module-level session or client across requests, or one `AsyncSession` across `asyncio.gather` tasks. Create it per request or per task.
- Calling `Base.metadata.create_all()` outside throwaway tests. The schema comes from Alembic.
- Starting `asyncio.create_task(...)` without keeping a reference, so the task can be garbage collected. Use `BackgroundTasks` or a queue.
- Catching bare `Exception` and returning 200. Let unexpected errors reach the handler that logs and returns 500.
- Setting `allow_origins`, `allow_methods`, or `allow_headers` to `["*"]` together with `allow_credentials=True`. With credentials, list each origin, method, and header.

## Testing
- Test through the app with `httpx.AsyncClient(transport=httpx.ASGITransport(app=app))` and `pytest-asyncio` or `anyio`, following whichever the repo already uses.
- `AsyncClient` does not run `lifespan`. When startup state matters, wrap the app in `asgi-lifespan`'s `LifespanManager`, or use `TestClient` as a context manager.
- Replace dependencies with `app.dependency_overrides` and clear them after each test.
- Isolate the database per test with a rolled-back transaction or a fresh schema. Build data with factories, not shared mutable fixtures.
- Cover the unhappy paths for each endpoint: 422 validation, 401 and 403 auth, and 404 not found.
- Run `alembic check` in CI so a model change without a migration fails, and test `upgrade head` on an empty database.

## Security
- Enforce authorization in a dependency so a route cannot forget it. Check object ownership in the query, not after loading.
- Build SQL only with bound parameters or the ORM. Use the password hashing library already in the repo (argon2 or bcrypt).
- Verify JWT signature, expiry, issuer, and audience, and pin the accepted algorithms. Keep access tokens short-lived.
- Limit upload size and validate content type. Do not echo internal error details to clients.
- Disable the interactive docs and schema (`docs_url=None`, `redoc_url=None`, `openapi_url=None`) in production when the API is not public.

## Done means
- Every applicable command in the Verify list has run clean.
- New behavior has a test; a fixed bug has a test that failed before the fix.
- The final message lists what changed, the commands run with results, anything not verified, and follow-ups you noticed but did not do.
